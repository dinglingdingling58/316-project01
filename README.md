# 316-project01
你现在是一个Python全栈开发专家。请根据以下需求编写一个模块化的、可维护的Python代码库。任务描述
开发一个「多格式文档静态结构扫描与元数据提取工具」。
程序需要：递归扫描指定目录，识别常见文档格式，提取结构化元信息（标题层级、主要段落数、代码块数量、链接数量、表格数量等），并生成结构化纯文本分析报告。同时对Python源代码文件进行简单静态检查（仅识别常见命名约定问题，不执行、不用ast）。功能需求 

程序应递归扫描输入目录（只处理指定扩展名文件） 

支持的文件类型（至少）：.md, .py, .txt, .rst, .html 

对于Markdown (.md) 文件：提取所有一级到四级标题（# ～ ####），统计每个层级的数量 

对于Python (.py) 文件：用正则粗略检查 

是否存在大量单字母变量（a,b,x,y,i,j等） 

是否存在下划线开头但不是__xxx__的名称（可能私有变量误用） 

统计函数/类定义数量

生成一份汇总报告（纯文本），保存为 analysis-report.txt 

报告中需包含每个文件的简要统计 + 全目录总体统计

强约束（必须严格遵守，写进系统提示的最显眼位置）路径约束 

程序必须使用以下两个固定目录：
输入目录： ./source_data/
输出目录： ./output_build/ 

除生成最终报告文件外，禁止在 ./source_data/ 目录下创建、修改、删除、重命名任何文件 

存在名为 .do_not_touch.cfg 的文件（用于标记不可碰目录），程序应读取它但绝不修改它

文件命名与结构约束 

所有Python模块文件名必须使用小写 + 下划线风格，并以以下前缀之一开头：
core_、scan_、parse_、report_、util_ 

禁止使用：main.py, app.py, run.py, init.py 以外的其他包初始化文件 

项目必须拆分成至少5个独立文件，且合理分层：├── main.py # 唯一入口，负责参数解析与流程调度 ├── core_scanner.py # 文件系统遍历、类型识别、文件过滤 ├── core_parser.py # 内容解析（md标题、py简单静态检查） ├── reporter.py # 报告生成、格式化输出 ├── utils/config.py # 常量、支持的后缀列表、配置读取 └── utils/validators.py # 路径、文件名合法性检查等小工具函数

技术约束 

只使用 Python 3.9 ~ 3.11 标准库（严禁使用第三方包，包括 pandas, pyyaml, markdown, beautifulsoup, ast 等） 

解析 Markdown 和 Python 文件时只允许使用字符串操作 + 正则表达式 

不要使用 pathlib（只用 os / os.path） 

错误处理要完备（使用 try-except），但不要打印堆栈，要优雅记录到报告中

输出要求
请直接开始撰写完整的代码结构，按文件逐一给出完整代码，不要省略任何部分。
代码风格：PEP 8，类型提示（使用 typing），防御性编程，清晰的函数职责划分。现在请开始生成上述项目的完整代码，按文件顺序输出。
